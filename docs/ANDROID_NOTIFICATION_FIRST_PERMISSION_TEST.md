# Android 첫 습관 알림 팝업 — PR #169 실기기 회귀 검증

기준: 2026-11-27 / 관련 코드 `components/byeolharu.tsx`, `mobile/packaged-guest/main.tsx`, `mobile/notifications/notification-permission-onboarding.js`.

## 검증 상태
- 통과(사용자 APK): 예시 습관 정리 및 과거 기록 보존, 습관 삭제 확인 문구/버튼, 상태 알림 색상·여백·4초 자동 숨김.
- 미확정: 최초 알림 안내 팝업과 `나중에 / 알림 설정하기 / 권한 거부` 세부 분기. **미검증을 실패나 통과로 바꾸지 않는다.**
- 웹/CI 검사는 Android 시스템 권한 창과 실기기 동작을 증명하지 않는다.

## 테스트 환경을 나누는 이유
PR #169 당시에는 기존 APK의 최초 안내 기록 또는 기기 opt-in 선택이 있으면 새 안내를 생략했다. 아래 P1 수정의 v2 정책에서는 실제 알림 수요가 있는 준비된 snapshot과 현재 OS 권한 상태, v2 안내 여부를 기준으로 한 번 안내한다. 이전 v1 안내만 확인한 기기도 v2 권한 안내 조건에 해당할 수 있다. 명시적 습관 opt-out은 존중하되 별도의 마무리 알림 수요는 독립적으로 고려한다. 일반 권한이 이미 허용되면 일반 OS 권한 요청은 생략한다.

**중요:** 현재 사용 중인 기기의 앱 데이터/저장 공간을 삭제하여 첫 실행을 재현하지 않는다. 기록 손실 위험이 있다. 첫 실행 테스트는 별도 에뮬레이터/테스트 기기의 신규 설치 환경에서 진행한다. 기존 기기는 반복 권유 없음과 명시적 알림 ON 복구 경로만 검증한다. 테스트용 앱 패키지는 기존 설치 앱과 사용자 데이터를 혼합하지 않는다.

## 케이스 A — 기존 설치 기기 (데이터 보존)
1. 앱 진입: 홈에 기존 인라인 알림 권한 배너가 없는지 확인. 사용자의 습관·기존 기록·계정이 유지되어야 한다.
2. 습관 생성 또는 편집에서 시간 지정 → 알림 ON → 저장: OS 허용 상태라면 저장 후 켜져야 한다. 이미 안내를 본 기기라면 중앙 **첫** 안내 팝업이 반복되지 않아야 한다.
3. Android에서 알림 권한이 차단된 상태라면 사용자 본인이 알림 ON을 누른 뒤에만 권한 요청/휴대폰 설정 안내가 제공되어야 한다. 앱 진입만으로 설정을 열지 않는다.

## 케이스 B — 신규 테스트 설치 (첫 알림 안내)
각 시나리오는 **서로 격리된 신규 설치 데이터 환경**으로 확인한다. 동일 프로필 재사용 시 최초 안내는 다시 나타나지 않는다.

## 회원 첫 로그인 및 권한 재확인 — P1 회귀 재검증

기준 main `a967` / 사용자 실기기 보고: 기존 회원 습관을 복원했을 때 알림 권한 확인 안내가 누락되는 경우가 있다. 기존 습관을 편집하지 않으면 편집기의 최초 안내 진입점에 도달하지 못하는 코드 경로를 확인했다. 아래 테스트는 수정 후 다시 실행하며, **사용자 보고를 자동화 또는 새 APK 실기기 통과로 바꾸지 않는다.**

- 최초 앱 실행은 습관이 없는 기기에서도 일반 알림(POST_NOTIFICATIONS)과 정확 알림(SCHEDULE_EXACT_ALARM) 상태를 각각 확인한다. 권한 **조회**는 허용하지만 시스템 권한 요청이나 휴대폰 설정 화면을 자동으로 열지 않는다. 한쪽 확인 실패는 다른 쪽 결과를 숨기거나 거부로 단정하지 않는다.
- 회원 로그인 직후 초기 빈/미수화 snapshot은 복원 완료가 아니다. 검증된 계정의 오늘 기록이 준비될 때까지 같은 계정의 기존 예약 및 습관 알림 선택을 보존하고, 이전 계정의 예약은 종전 계정 경계 규칙에 따른다. 로그인·편집·기록·확인 팝업을 밀어내지 않는다.
- 실제 복원된 습관에 유효한 예정 시각과 알림 ON 설정이 있고, 기기 최초 안내에 해당하며 OS 권한이 필요한 경우 홈에서 한 번 안내한다. 사용자가 허용/나중에/거부를 선택해도 기존 회원 습관의 `alarmEnabled`, 과거 기록, 회원 Outbox, 전역 기기 opt-in을 임의로 변경하지 않는다. 새 습관 생성에서 권한 거절 시 해당 새 습관 알림을 OFF로 저장하는 B1/B3 정책과 구분한다.
- 정확 알림은 선택형 특별 접근 권한이다. 사용자가 앱의 통합 CTA ‘알림 설정하기’를 선택하면 일반 권한을 실제로 허용한 뒤 필요한 경우에만 정확 알림 설정을 연다. 각 Android OS 화면의 승인/취소는 독립이며 정확 권한 차단·철회 시 기존 일반 예약 정책을 사용한다. 일반 권한 복구 설정은 Activity 반환과 실제 foreground, 동일 세션·현재 계정/화면·실제 허용 확인을 요구한다. 임의 복귀/프로세스 재시작은 자동 연쇄 요청을 시작하지 않는다. 반복 권유는 하지 않되 관련 명시적 행동에서는 최신 권한을 재확인한다.

각 케이스는 별도의 안전한 테스트 설치/테스트 계정에서 실행한다. 복원 테스트는 로그인 전후 습관 설정·오늘/과거 기록의 일치와 실제 알림 수신 여부까지 확인한다. 상태는 모두 수정본 기준 **NOT RUN**이다.

자동 테스트는 권한 브리지 호출 횟수·설정 복구 결정·알림 대상 해석을 검증하지만 실제 OS 팝업, 예약 전달, 화면 전환 및 접근성 결과를 증명하지 않는다. 위 케이스와 B2/B6 새 검증 결과는 모두 실기기 **미검증**이다.

## 결과 기록
- APK 및 설치 경로(서명/패키지), Android 버전, 기기/에뮬레이터, 앱 기존/신규 설치 여부, 앱 테마.
- 각 케이스의 **통과/실패/미검증** + 실패 시 정확한 조작 순서·화면·권한 상태.
- 권한 OFF/ON 시 기존 사용자 기록, 알림 설정 및 예약이 보존되는지 확인.
- 테스트 후 **운영 데이터 삭제, Supabase 초기화, 다른 사용자 계정 사용 금지**.

## 인수 기준
- B1~B3 및 B6~B7 실기기 분기가 확인되기 전 #160/#169의 권한 UX를 단말 검증 완료로 선언하지 않는다.
- R01~R07 및 R09~R10을 실기기에서 통과하고 복원된 ON 설정·기록·예약의 불변식을 확인하기 전 이번 회원 첫 로그인 P1 회귀 및 관련 출시 검증은 열린 상태로 둔다. R08 접근성 및 R11 버전/상태 분기도 별도 기록한다.
- #188 이동 케이스의 실기기 검증을 완료하기 전 해당 이슈 또는 관련 출시 검증을 통과 처리하지 않는다.
- Android CI 및 이 문서의 코드 계약 검사는 변경 누락 방지에 한정한다.
- 예시 정리·삭제 확인·상태 알림은 이미 통과한 동작을 유지하고 회귀만 확인한다.
