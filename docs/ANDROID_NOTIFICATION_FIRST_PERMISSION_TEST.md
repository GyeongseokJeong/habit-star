# Android 첫 습관 알림 팝업 — PR #169 실기기 회귀 검증

기준: 2026-11-23 / 관련 코드 `components/byeolharu.tsx`, `mobile/packaged-guest/main.tsx`, `mobile/notifications/notification-permission-onboarding.js`.

## 검증 상태
- 통과(사용자 APK): 예시 습관 정리 및 과거 기록 보존, 습관 삭제 확인 문구/버튼, 상태 알림 색상·여백·4초 자동 숨김.
- 미확정: 최초 알림 안내 팝업과 `나중에 / 알림 허용하기 / 권한 거부` 세부 분기. **미검증을 실패나 통과로 바꾸지 않는다.**
- 웹/CI 검사는 Android 시스템 권한 창과 실기기 동작을 증명하지 않는다.

## 테스트 환경을 나누는 이유
기존 APK에서 이미 기기별 `PERMISSION_OFFER_SEEN_KEY`가 저장되어 있거나 `OPT_IN_KEY`가 ON/OFF로 설정되었으면 처음 안내는 **의도대로 나오지 않는다**. OS 권한이 이미 허용되었어도 첫 안내는 생략된다.

**중요:** 현재 사용 중인 기기의 앱 데이터/저장 공간을 삭제하여 첫 실행을 재현하지 않는다. 기록 손실 위험이 있다. 첫 실행 테스트는 별도 에뮬레이터/테스트 기기의 신규 설치 환경에서 진행한다. 기존 기기는 반복 권유 없음과 명시적 알림 ON 복구 경로만 검증한다. 테스트용 앱 패키지는 기존 설치 앱과 사용자 데이터를 혼합하지 않는다.

## 케이스 A — 기존 설치 기기 (데이터 보존)
1. 앱 진입: 홈에 기존 인라인 알림 권한 배너가 없는지 확인. 사용자의 습관·기존 기록·계정이 유지되어야 한다.
2. 습관 생성 또는 편집에서 시간 지정 → 알림 ON → 저장: OS 허용 상태라면 저장 후 켜져야 한다. 이미 안내를 본 기기라면 중앙 **첫** 안내 팝업이 반복되지 않아야 한다.
3. Android에서 알림 권한이 차단된 상태라면 사용자 본인이 알림 ON을 누른 뒤에만 권한 요청/휴대폰 설정 안내가 제공되어야 한다. 앱 진입만으로 설정을 열지 않는다.

## 케이스 B — 신규 테스트 설치 (첫 알림 안내)
각 시나리오는 **서로 격리된 신규 설치 데이터 환경**으로 확인한다. 동일 프로필 재사용 시 최초 안내는 다시 나타나지 않는다.

| 상황 | 조작 | 기대 결과 |
|---|---|---|
| B1: 나중에 | 신규 환경, OS 권한 요청 전 → 습관 생성 → 시간 지정 → 기본 알림 ON 저장 → '나중에' | 중앙 안내 팝업, OS 권한 팝업 없음, 습관 저장, 해당 습관 알림 OFF, 다음 진입 자동 재안내 없음 |
| B2: 허용 | 신규 환경, OS 권한 요청 전 → 습관 알림 직접 ON → '알림 허용하기' → OS 허용 | 중앙 안내 후 OS 권한 창, 허용 후 습관 알림 활성화·저장, 자동 재안내 없음 |
| B3: 거부 | 별도 신규 환경 → 중앙 안내의 '알림 허용하기' → OS 거부 | 습관 저장 가능, 알림 OFF, 앱 진입만으로 재요청·강제 설정 이동 없음; 이후 직접 ON 시 권한 복구 경로 제공 |
| B4: 이미 허용 | OS 권한이 사전에 허용된 격리 테스트 환경 → 습관 알림 ON | 최초 안내 생략, 사용자가 ON한 습관만 활성화 |
| B5: 웹 분리 | 동일 기능을 웹/PWA에서 실행 | Android 전용 첫 알림 팝업 없음 |

## 결과 기록
- APK 및 설치 경로(서명/패키지), Android 버전, 기기/에뮬레이터, 앱 기존/신규 설치 여부, 앱 테마.
- 각 케이스의 **통과/실패/미검증** + 실패 시 정확한 조작 순서·화면·권한 상태.
- 권한 OFF/ON 시 기존 사용자 기록, 알림 설정 및 예약이 보존되는지 확인.
- 테스트 후 **운영 데이터 삭제, Supabase 초기화, 다른 사용자 계정 사용 금지**.

## 인수 기준

- Android CI 및 이 문서의 코드 계약 검사는 변경 누락 방지에 한정한다.
- 예시 정리·삭제 확인·상태 알림은 이미 통과한 동작을 유지하고 회귀만 확인한다.
