## 1. 확정된 제품 정책 (STEP 1–4)

| 항목 | 확정 정책 |
| --- | --- |
| 성장 범위 | 사용자 **전체 습관의 실천**이 단일 별자리에 기여. 습관별 별자리 여러 개는 만들지 않음 |
| 성장 단위 | 로컬 캘린더 날짜별 서로 다른 완료 습관 각 1점, **하루 최대 3점** |
| 완료 판정 | `completed === true`; `rating === 0`인 단순 체크도 인정. 별점 크기는 가중치 없음 |
| 성장 단계 | Stage 1: 0–6, Stage 2: 7–19, Stage 3: 20–49, Stage 4: 50–99, Stage 5: 100–199, Stage 6: 200점 이상 |
| 최고 단계 이후 | 새 공식 Stage를 늘리지 않고 Stage 6의 별빛·장식이 점진적으로 풍성해짐 |
| 아트 구조 | **중심별 + 가지형 확장**을 신화적 별빛 사슴의 뿔·실루엣·오로라로 발전. 최종 Stage 6은 사용자 승인된 은은한 금빛 사슴 이미지가 시각 기준 |
| 현재 점수/단계 | 현재 유효 기록에서 **재계산**. 과거 기록 취소로 실제 점수가 줄면 Stage 하락 가능 |
| 무활동 처리 | 단순 미실천/미접속은 누적 점수 감소나 별자리 퇴화 원인이 아님 |
| 우선순위 | 성장 계산 기반 → **별자리 시그니처 경험 먼저 구현** → 이후 V3.1 영구 뱃지·이미지 공유 결합 |

계산 정의:
```ts
dailyPoints(day) = Math.min(3, countDistinctCompletedHabitIds(day))
totalPoints = sum(dailyPoints(day)) // 해당 사용자 범위의 신뢰 가능한 모든 날짜
```

- 오늘과 과거 History 병합 시 동일 날짜를 중복 합산하지 않는다.
- 완료 습관이 5개인 날은 실제 완료 5건, 별자리 성장 +3점으로 구분한다.
- 예정일이 아닌 날의 자발적 실천도 완료라면 인정한다.
- 완료→취소→복구, 별점 변경, 여러 차례 수정, 날짜·타임존 경계에서 결과가 결정론적으로 같아야 한다.
- 비회원/회원 저장 범위를 섞지 않는다. 로그인·오프라인·복원·클라우드 충돌 해결 시 원본 기록 기준으로 계산한다.

## 2. 시그니처 아트의 비타협 품질 기준

**화면의 주변 UI는 간결하게 유지하지만, 별자리 아트 자체는 영화적인 깊이와 강한 미적 임팩트를 목표로 한다.** 평범한 별 아이콘 몇 개와 단순한 연결선만으로 최종 아트를 대체하지 않는다.

아트 방향:
- 깊은 midnight navy 하늘, 겹겹이 쌓인 plum/violet 성운, champagne-gold의 중심별/연결별, 섬세한 광채·입자·공간감.
- **동일한 신화적 별빛 사슴을 향해 성장하는 서사**가 Stage 1에서 6으로 완성된다. 중심 광원과 상징적 뿔/오로라의 시각적 연속성을 지키고, 무관한 그림으로의 교체는 금지한다. 초기 고정 좌표 SVG 실험은 최종 아트 구조가 아니다.
- 최종 Stage 6이 명확한 시그니처 작품으로 느껴지되, 초기 Stage 1도 허전한 플레이스홀더가 아닌 아름다운 출발점이어야 한다.
- 배경·별·선·광채·입자에 레이어를 쓰되 읽기 쉬운 텍스트, 저사양 모바일, 두 테마, 축소 동작 설정을 고려한다.
- 아름다움 검증은 스크린샷/실화면을 포함한다. 단순 타입검사·렌더 테스트 통과로 디자인 품질을 보증했다고 선언하지 않는다.

### Stage별 아트 디렉션

| 단계 | 이름 | 조형 변화 |
| --- | --- | --- |
| 1 | 첫 번째 별빛 | 보석 같은 중심별, 집중된 광휘, 깊은 고요함 |
| 2 | 별이 모이는 밤 | 주변 주별 2개와 우아한 첫 연결·황금빛 궤적 |
| 3 | 별빛의 연결 | **사용자 승인 수정:** 연결되는 별무리가 주인공; 사슴은 희미한 머리·목·뿔의 징후만 드러나는 반투명 성운 형태, 전신·뚜렷한 몸체는 금지 |
| 4 | 나의 작은 별자리 | 식별 가능한 신화적 사슴과 분기형 빛의 뿔이 등장 |
| 5 | 찬란한 별자리 | 청보라 몸체·샴페인 골드 윤곽·풍성한 성운이 성체 직전의 장엄함을 완성 |
| 6 | 빛나는 은하 | **승인된 은은한 금빛 별빛 사슴**: 거대한 황금 뿔, 유려한 오로라, 크리스털 무대, 눈부신 은하 고리 |

Stage 6 이상은 본체·주요 별 좌표를 바꾸지 않고 주변 장식만 추가한다. Stage 간 차이가 모바일 320 CSS px에서도 분명해야 하며 Stage 5와 6의 시각적 차이는 특히 인상적이어야 한다.

### 아트 구현 전략

- 승인된 Stage 6 아트를 기준으로 레이어형 원화를 역설계한다. 연결 별 좌표가 필요한 부위는 결정론적으로 고정하되, 사슴 형상은 SVG 노드·선에만 구속하지 않는다. 벡터/레이어드 래스터/Canvas·애니메이션을 표현력·성능·해상도로 비교한다.
- 화려한 정적 시각 효과와 **절제된 동작**을 구분한다. 사용자 입력/진입 때 과도하게 반복되는 연출, 불필요한 GPU 부하는 피한다.
- 단계 전환은 추가된 별/가지의 공개가 핵심. 기록 수정으로 단계가 낮아질 때 벌점·파괴 효과는 넣지 않는다.
- 모션 감소 설정에서는 주요 의미와 그림이 그대로 전달되어야 한다.
- 랜덤 요소가 필요하면 안정적인 seed·미리 확정된 좌표만 사용해 리렌더·동기화 후에도 재현 가능해야 한다.
- 아트는 추후 이미지 공유에 재사용할 수 있어야 하지만 V3.2에서 공유 기능까지 미리 구현하지 않는다.



## 2A. Stage 6 시그니처 아트 — 사용자 승인 시각 기준 (2026-11-17)

**상태: Stage 6 시각 기준 승인. 아직 앱 구현·원본 그래픽 에셋 커밋·Stage 1–5 최종 승인 이전.**

사용자가 대화에서 최종 승인한 작품은 **황금빛이 은은하게 도는 신화적 별빛 사슴**을 중심으로 한 세로형 아트 카드다. 기존 '별 점과 선만으로 이루어진 추상 별자리'를 최종 결과로 해석하지 않는다. 신화적 사슴의 몸체 자체가 성운과 연결된 별자리 형상이다.

**정확한 시각 출처:** 본 프로젝트 대화 중 '사슴도 살짝 금빛이 돌면 좋겠어' 이후 생성된 Stage 6 단독 세로 이미지, 사용자가 '좋아! 이게 stage6 이야. 시각적 기준에 사용해.'라고 승인한 이미지. 검토용 별도 파일 `stage-06-approved-reference.png`(968×1625 PNG), SHA-256 `f1d01958abd2d09d55e299ef82d0f7746a469f76715ccc0fc20eee7f7eeea39c`. **현재 이미지는 대화 검토 산출물이며 이 GitHub PR에 바이너리가 포함되어 있지 않다.** 구현 담당자는 승인 이미지 원본을 참조 파일로 전달받아야 하며, 문장만 읽고 '비슷한 사슴'으로 대체하여 승인됐다고 주장하면 안 된다.

### 승인된 아트의 불변 시각 조건

- **상징물:** 기품 있고 비례가 아름다운 *한 마리의 성스러운 별빛 사슴*. 사슴이 명확하게 식별되며, 단순한 별 아이콘/선을 중심으로 돌아가지 않는다.
- **사슴 몸체:** 진주빛 아이보리·라벤더·청보라색의 발광하는 몸체. 얼굴, 목, 가슴털, 몸통 윤곽, 다리 가장자리에는 **은은하지만 확실한 샴페인 골드 하이라이트**가 번진다. 전체 사슴을 단색 순금으로 바꾸는 것은 승인된 균형을 깨뜨린다.
- **뿔:** 넓고 우아하게 펼쳐진, 나뭇가지처럼 분기하는 거대한 황금빛 별자리 뿔. 중심별과 작은 점광원, 우아한 빛의 선이 뿔과 유기적으로 연결된다.
- **흐름:** 사슴 뒤편과 꼬리/어깨 주변에서 보라·블루·핑크·금빛의 유성/오로라 리본이 유려하게 흐른다. 별과 성운이 실루엣을 확장한다.
- **무대/배경:** 깊은 미드나이트 네이비 우주, 신비로운 플럼·바이올렛 성운, 금빛 은하 궤도, 보랏빛·푸른빛 수정 결정, 발굽 아래 빛나는 회전 고리/성좌 플랫폼, 금빛 광채와 미세 별빛.
- **전체 구도:** 세로 카드 중앙에 사슴을 크고 선명하게 배치. 뿔과 사슴 몸체, 크리스털과 플랫폼이 단계 완성의 압도적 보상으로 보인다. 네비게이션·제품 UI까지 과도하게 장식할 필요는 없다.
- **타이포그래피:** `STAGE 6`, `빛나는 은하`, `200점 이상` 및 하단의 짧은 감성 문구는 아트와 **별도 UI/텍스트 레이어**로 구현해 한글 품질과 접근성을 확보한다. 승인 이미지에 텍스트 렌더 오탈자가 있다면 최종 앱 카피로 전사하지 않는다.
- **품질 판정:** 최종 아트가 승인 이미지와 분위기/실루엣/금빛 포인트/광량·층위에서 실질적으로 동일한 고급감을 내야 한다. SVG 원과 선만 있는 결과물은 합격 불가.

### Stage 1–5 역설계 가이드 (최종 승인 전 시안)

Stage 6의 사슴·뿔·오로라·성좌 플랫폼을 **같은 한 작품의 누적 성장**으로 재해석한다. 이전 단계의 중심 광원과 특징적인 성좌 연결이 나중 단계에서도 유지되되, 그림 레이어를 정확히 같은 좌표의 SVG 그래프로 강제할 필요는 없다. **상징과 실루엣의 연속성**이 우선이다.

- Stage 1: 보석 같은 첫 중심별, 장엄한 신화적 세계의 씨앗
- Stage 2: 황금빛 별무리와 사슴을 암시하는 빛의 흐름
- Stage 3: 첫 뿔/사슴의 윤곽이 별자리·오로라에서 드러남
- Stage 4: 알아볼 수 있는 신화적 사슴의 몸체와 분기된 뿔
- Stage 5: 정교한 뿔·성운 흐름·금빛 윤곽, 거의 완성된 성체
- Stage 6: **승인된 골드 포인트 별빛 사슴**과 수정 무대·은하 궤도의 최종 작품

**Stage 3 수정안 사용자 승인 (2026-11-17):** 사슴 형상이 너무 일찍 완성되어 보이지 않도록 몸체·얼굴·다리는 흐리고 반투명한 성운 윤곽으로 제한한다. 오히려 금빛·보랏빛 별의 개수와 별자리 점광원·연결성이 시각적 주인공이어야 한다. 머리와 작은 뿔은 일부만 암시하고 뿔의 전체 분기·전신 실루엣·뚜렷한 다리는 Stage 4 이후로 넘긴다. 사용자가 승인한 역설계 수정 비교 시안이 있고, 해당 대화 원본 이미지를 실제 제작 시 참조해야 한다. 수정 전 Stage 3 선명한 사슴 그림은 더 이상 승인된 기준이 아니다.

Stage 1–2, Stage 4–5의 개별 고해상도와 모바일 표현은 다음 사용자 리뷰에서 따로 확인한다. Stage 6 이후 장식 임계값 250/300/350/400은 여전히 *미확정 제안*이다.

**기존 `design/constellation-v3-2/svg/*.svg`와 `layout.prototype.json`은 승인된 사슴 아트보다 먼저 만들어진 별·연결선 원형이며, 이제 최종 참조나 출시 가능한 에셋이 아니다.** 사슴 아트로의 재설계를 위해 역사적 참고 자료로만 둔다.

## 3. 미확정 사항: 확정 정책으로 고정하거나 몰래 하드코딩 금지

1. Stage 1–5의 개별 고해상도 아트는 사용자 시각 검토 전이며, **Stage 3의 희미한 형상 + 연결되는 별 중심**은 사용자 승인된 가이드다.
2. Stage 6 이후 장식 임계값 **250/300/350/400점**과 400점 상한은 제안안이다. 제품 정책 확정 전에는 변경 가능한 설정으로만 취급.
3. 아트 제작 방식(SVG/Canvas/정적 레이어 조합), 정확한 별 좌표, 장면별 모션 길이, 추가 성운 레이어 수는 아트·기기 성능 검증 후 결정.
4. 상세 성장 화면의 최종 배치·홈 진입 위치는 기존 StarlitHero 및 ‘나의 별 기록’ 기능과 중복되지 않는 시안을 검토 후 확정.

**결정이 바뀌면 이 문서를 우선 갱신하고 관련 스킬/디자인/테스트를 함께 재검토한다. 오래된 제안을 새 확정 사항보다 우선하지 않는다.**

## 4. 구현 경계 및 리스크

- `components/byeolharu.tsx`: 오늘 기록과 과거 기록을 합친 `allHistory`, 기존 홈 지표.
- `components/starlit-hero.tsx`: 오늘의 실천에 대한 별빛 히어로(유지 대상).

V3.2는 우선 원본 기록을 읽는 **순수 계산 엔진 + 프레젠테이션**으로 설계한다. 새 영구 DB 테이블은 기본 요구사항이 아니지만, 샘플 출처 구분·과거 기록 보존 등 신뢰성 문제가 확인되면 데이터 모델 변경 필요성을 근거와 함께 보고하고 설계를 수정한다.

**중요한 기존 코드 검증 항목**: 신규 게스트 샘플에 초기 완료 상태가 포함될 수 있다. 시연용 샘플을 실제 사용자의 완료 실천으로 계산해서는 안 된다. 사용자가 나중에 실제로 샘플 습관을 기록했다면 그 실천은 인정해야 하므로, 원본 훼손이나 단순한 습관명 필터링으로 해결하지 않는다.

과거 삭제된 습관의 완료 이력은 원본에 보존된 범위에서 합산하며, 기록이 없는 날짜를 추정 완료로 간주하지 않는다.

**V3.1과의 경계**: V3.1에서 확정된 영구 보유 성취 뱃지는 별도 역사적 이벤트이며, V3.2의 현재 성장 점수/Stage 재계산 규칙과 혼합하지 않는다.

## 5. 필수 검증 및 단계별 진행

1. **아트 사양 및 6단계 갤러리 검토**: Stage 1–6 원본 좌표의 연속성, 차별화, 시그니처 품질, 모바일 실제 크기 시안. 사용자 검토 전 단순 플레이스홀더를 최종품으로 취급하지 않음.
2. **Growth Engine**: 날짜별 0/1/2/3/5건 → 0/1/2/3/3점, 동일 ID 중복 제거, 별점 변경, 완료 취소, 샘플 출처, 타임존, 계정 분리.
3. **Stage/Art Engine**: 임계값 0/6/7/19/20/49/50/99/100/199/200, Stage 6 이후 장식, 고정 좌표·연결선 존재 검증, 낮아진 Stage에서 불필요한 부정 연출 없음.
4. **UI 연동**: 기존 홈의 실천 기록 UX와 StarlitHero 유지; 성장 화면 진입, 라이트/다크, 320px 모바일, 키보드·접근성·모션 감소 검증.
5. **회귀/리뷰**: `pnpm typecheck`, `pnpm test`, 관련 `pnpm test:e2e`, `pnpm build`; 저장/동기화 수정 시 별도의 DB/클라우드 검증. 실행하지 못한 검사를 통과라 표기하지 않음.

서명 아트의 최종 합격은 **6개 단계 시안의 실화면 확인 + 실제 사용자 흐름에서 성장 체감 확인**까지 포함한다. 제품 방향 변경이나 구현 중 발견된 오류는 이 문서와 관련 하네스 규칙을 동기화해 고친다.
