## 추가 인수 기준

| 시나리오 | 기대 결과 |
| --- | --- |
| 앱에서 1~5점 완료 후 완료 표시 위젯에서 취소 | 미완료·0점으로 정상 반영, 별점 매트릭스·진행률 갱신 |
| 최근 앱 제거 후 같은 위젯 취소 | 최신 원본 저장, 오늘의 미래 알림만 재예약; 지난 알림은 재예약하지 않음 |

| 중복·오래된 위젯 탭 / 다른 계정 / 날짜 변경 | 안전하게 거부, 최신 상태 덮어쓰기 없음 |

CI 및 Android PR/main 빌드, 동일 서명 업데이트, 회원/비회원 실기기 확인 전 비공개 테스트 배포 보류. Play 서명 AAB는 병합 main에서만 생성한다. 운영 DB 변경 없음.

## 관점 검토

- 1차 (UX·사용자 vs 아키텍처·데이터): 완료 취소 의도를 우선하되 1~4점의 자동 덮어쓰기는 허용하지 않는다. 최신 검증된 완료 행에 대한 명시적 취소에만 범위를 넓히고 기존 메모 및 설정/과거 데이터 보존·revision/version 검증을 유지한다.
- 2차 (QA·Android·보안): 앱 종료 시 재예약 검증의 이전 정책을 반례로 확인했다. 원본과 cold 알림 결정 양쪽을 맞추고, 회원/비회원 모든 1~4점 cold 경로 및 기존 중복·계정·잘못된 별점·지난 시간 보호 테스트를 포함한다. 실제 기기의 OS 알림 및 Play 업데이트는 별도 검증이다.

동일 모델의 구조화된 역할 관점 검토이며 독립 전문가·실기기 검증을 대체하지 않는다.
