# 별하루 Android 0.1.5 — 비공개 테스트 후보

- 패키지: `app.byeolharu.android` / versionName `0.1.5` / 후보 versionCode `6`.
- 기능 기준 main: `d47d5a04827561706ad78eb3d471818afe71ea7a` ([#245](https://github.com/GyeongseokJeong/habit-star/pull/245), [#246](https://github.com/GyeongseokJeong/habit-star/pull/246)).
- 직전 저장소 버전은 code 5. 실제 Play 최고 사용 versionCode는 아직 확인되지 않았다. 6 이상을 이미 사용했다면 서명 전 후보를 다시 올린다.
- 기존 패키지, 업로드 키, 위젯 및 알림, 기록·동기화 정책을 유지한다. 이 PR은 버전과 배포 계획만 변경하며 운영 DB에 손대지 않는다.

## 비공개 테스트 시작 전 게이트

1. 후보 PR과 병합 main의 CI verify/cloud, Android 빌드 성공 및 SHA 확인. #245·#246 PR의 verify/cloud와 #246 Android 빌드는 성공했으나 운영 검증은 별도다.
2. [회원 탈퇴 운영 게이트](../ACCOUNT_SELF_SERVICE_DELETION.md)에 따라 정확한 운영 프로젝트의 기존 마이그레이션 이력과 계정 FK·기존 JWT 차단을 확인한다. 신규 마이그레이션 적용과 함수 배포는 별도 승인·백업/복구 검토 후 순서대로 진행한다. 실제 회원 대신 테스트 전용 계정으로 검증한다. 미검증 상태에서 탈퇴 지원을 내세워 배포하지 않는다.
3. 웹의 `/privacy`, `/account-deletion` 실제 공개 접근과 Data safety·앱 콘텐츠, 스토어 정보·지원 이메일 `jasset.biz@gmail.com`, 실제 화면 스크린샷 및 심사자 접근 준비를 확인한다. [스토어 등록 자료](STORE_LISTING_KO.md) 활용.
4. 모든 Play 트랙/앱 번들의 실제 최고 사용 versionCode 확인 후, main의 Android Shell PoC에서 `sign_internal=true`와 확인된 `highest_play_version_code`로 서명 AAB 생성. SHA·번들 해시·package·SDK·version·업로드 인증서 검증. 코드 5를 추정해 입력하지 않는다.
5. 테스트 참여자 배포 전 기존 Play 설치본 업데이트와 아래 QA 핵심 기기 검증을 마친다. 운영 및 Play 업로드·배포 승인은 구분한다.

정확한 계정의 Console에서 비공개 테스트 트랙을 설정한다. 신규 개인 계정의 프로덕션 액세스 조건이 적용되면 최소 12명이 연속 14일 옵트인해야 하므로, 자발적 참여자 15~20명을 모집하는 것을 권장한다. 내부 테스트 참여자는 내부 테스트에서 나간 후 비공개 테스트에 참여한다. 등록 이메일/Google 그룹과 참여 링크를 통해 실제 참여·사용을 확인하고, 문의·오류·개선 의견을 최소한의 정보로 정리한다. 첫날 설치 및 핵심 흐름, 중간 위젯/알림·기록 사용, 마지막 날 유지 상태와 피드백을 점검한다. 개인정보가 포함된 기록이나 스크린샷은 요청하지 않는다. 기간 충족 및 피드백 반영 후 프로덕션 액세스를 신청하고 별도 승인 후 정식 출시한다.

공식 참조: [신규 개인 계정 테스트 조건](https://support.google.com/googleplay/android-developer/answer/14151465), [테스트 트랙 설정](https://support.google.com/googleplay/android-developer/answer/9845334), [계정 삭제](https://support.google.com/googleplay/android-developer/answer/13327111).

## 검토 및 판단

release + android route, 동일 모델 구조화 관점 검토 (실제 독립 에이전트/참여자 조사 아님): PM·사업·마케팅·사용자·운영·QA·Android·보안.
- 1차: 기존 code 5 재사용 및 즉시 테스트 전환 제안에 대해 Android는 버전 충돌과 구버전 탈퇴 UI, QA/보안/운영은 서버 적용 누락 위험을 지적했다. PM·사용자·마케팅/사업은 실제 서비스 동작·신뢰와 조기 피드백의 균형을 요구했다. 후보 6으로 분리하고 운영·Play 확인을 차단 게이트에 둔다.
- 2차: QA/Android는 자동화 성공만으로 실기기·서명 업데이트를 보장하지 않음을 확인했다. 운영/보안은 승인 없는 운영 변경·실사용자 삭제 금지를 재확인했다. 사용자/PM/마케팅/사업은 12명 이탈 위험과 꾸준한 실제 이용·지원 경로의 필요성을 검토하여 15~20명 자발적 모집 및 실사용 피드백 계획을 유지한다. 버전 준비는 가능하나 Console·운영·실기기 증거는 N/E로 남기고 배포 보류한다.
