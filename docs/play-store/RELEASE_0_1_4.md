# 별하루 Android 0.1.4

Play 내부 테스트 후보: `0.1.4` / versionCode `5` / `app.byeolharu.android`.
기능 기준 main: `2fc29444add92e8e471aaddf52ed8beee1bbd37a` ([#242](https://github.com/GyeongseokJeong/habit-star/pull/242), [#243](https://github.com/GyeongseokJeong/habit-star/pull/243)).
패키지명·업로드 서명키·데이터 저장 및 동기화 정책을 유지한다. 두 기능 PR에는 신규 DB 마이그레이션이 없다.

## Google Play 변경사항 (ko-KR)

```text
별점 매트릭스에 예정된 습관 전체의 실천 정도를 반영하도록 개선했습니다.
새 버전을 앱에서 확인하고 편리하게 업데이트할 수 있습니다.
```

## 배포 조건

1. 버전 변경 PR 및 최종 main의 CI를 통과시키고, 해당 SHA의 Android AAB/APK 빌드와 아티팩트 검증을 확인한다.
2. 0.1.3까지의 운영 DB/개인정보·계정 삭제 관련 선행 게이트는 [0.1.3 릴리즈](RELEASE_0_1_3.md)를 따른다. 운영 변경 여부를 추정하지 않는다.
3. Play Console의 모든 트랙/앱 번들에서 실제 최고 사용 versionCode가 5 미만인지 확인한다. main의 Android Shell PoC 수동 실행에서 `sign_internal=true`와 확인된 `highest_play_version_code`를 입력한다.
4. 서명 AAB의 패키지·버전·소스 SHA·업로드 인증서·해시를 대조하고 내부 테스트 트랙에 업로드한다. 테스트 서명 APK는 Play 설치본의 업데이트 검증에 쓰지 않는다.
5. 기존 Play 설치본에서 M1~M3/U1/R1 검증 후, 0.1.4 자체의 인앱 업데이트 기능은 더 높은 versionCode를 가진 후속 테스트 릴리즈에서 U2~U4로 검증한다. 실제 제공 여부는 Play 트랙/계정/전파 상태에 따른다.
6. 서명, 업로드, 운영 DB 변경 및 공개 출시 검증·승인은 구분한다. 미확인을 통과로 처리하지 않는다.
