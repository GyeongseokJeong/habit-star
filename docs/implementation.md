# 구현 및 리뷰 단위

이 변경은 main `3e11a459037d1b6f65e8f07a7af30bab0efc7b76`의 동작을 기준으로 구현했습니다. 별도 PR 게시나 운영 배포는 수행하지 않습니다.

## 데이터와 경계

UI 조회 모델은 기존 Habit을 유지합니다. 영속 모델은 습관 정의, 날짜, 날짜별 전체 스냅샷으로 분리합니다. payload JSONB에는 공통 UI 속성을 보존하고 DB 함수에서 타입·길이·범위를 검증합니다. 사용자/날짜/습관 외래키와 PK, 버전, 삭제 표식은 DB 컬럼으로 관리합니다. 클라이언트가 테이블에 직접 쓸 권한은 없습니다.

IndexedDB의 scopes 트랜잭션이 데이터와 Outbox를 함께 저장합니다. v1 원문 백업은 파싱보다 먼저 별도 저장합니다. 백업 실패 시 초기화도 중단합니다. 정상 행만 변환하고 예외는 원문·검증 경로와 함께 보존합니다. 미래/미분류 날짜를 임의로 오늘로 옮기지 않습니다.

회원은 서버 확인을 통과한 사용자로 공간을 선택합니다. 오프라인 재진입은 기존 세션과 마지막 검증 사용자 ID가 일치할 때만 로컬 캐시를 사용하며, 이것은 서버 권한이 아닙니다. 모든 RPC는 다시 사용자 검증과 서버 소유권 검사를 통과해야 합니다. 브라우저 프로필 자체 접근/XSS로부터의 암호학적 격리는 제공하지 않습니다.

SyncEngine은 먼저 변경을 받고 기존 명령의 base를 유지하여 CAS를 수행합니다. 전송 성공 후 뒤따르는 미전송 작업의 필드 차이만 새 base에 적용합니다. 충돌은 명령 전체를 보존하며 관련 없는 명령은 계속 전송합니다. 같은 기록의 추가 편집은 충돌 해결 후 허용합니다. 별점과 완료는 하나의 병합 단위이고 메모는 자동 연결하지 않습니다.

서버의 사용자별 잠금이 데이터·멱등 결과·revision·변경 로그를 직렬화합니다. 초기/증분 결과는 동일한 frozen snapshot에서 200행씩 전송합니다. 커서는 마지막 페이지를 로컬에 반영할 때만 진행합니다. snapshots는 재요청 때 24시간 이상 된 해당 사용자의 것만 정리하며, 기록·작업 ID·충돌은 자동 삭제하지 않습니다.

가져오기는 200행 staging, 원문 콘텐츠 SHA-256 및 DB의 JSON 동등성·건수 검사, 단일 commit으로 처리합니다. journal에 동결된 행을 저장해 중단 후 재개합니다. 동일 source/hash는 같은 배치를 반환하고 중복 적용하지 않습니다. 같은 이름의 서로 다른 UUID를 자동 통합하지 않습니다.

## 검증 범위 구분

`pnpm test`는 도메인/IndexedDB/전송 시뮬레이션입니다. `pnpm test:db --postgres`는 실제 PostgreSQL에서 RLS와 RPC를 검사하지만 Supabase Auth는 최소 identity contract로 대체합니다. `pnpm test:e2e`는 실제 브라우저 비회원 회귀입니다. `pnpm test:e2e:cloud`는 로컬 Supabase Auth의 메일 확인·재설정·실제 세션과 두 브라우저의 오프라인 동기화·충돌 해결·로그아웃 격리를 검증합니다. 운영 도메인의 SMTP와 별도 실제 기기 검증은 출시 전 수행합니다. 운영 배포/베타 전환/운영 복원 연습은 자동으로 수행하지 않습니다.

설계서의 선택 기능 중 Realtime, 서버 푸시, 소셜 로그인, 과거 기록 편집, 자동 보존 기간 정리는 추가하지 않았습니다. 지원하지 않는 Web Locks 환경에서는 서버 멱등성으로 중복 실행을 막으며 탭당 polling이 발생할 수 있습니다.

## 이번 환경에서의 검증

- 타입 검사와 도메인·IndexedDB·인증 리디렉션 테스트 통과.
- 비회원 브라우저 회귀 5개 통과: v1 원문 보존, 손상 데이터, 탭 간 반영, 새 브라우저 백업 복원.
- 실제 로컬 Supabase의 SQL/RLS/RPC 테스트와 회원 브라우저 통합 2개 통과.
- 전체 스택 시작 시 내부 IP 헬스체크가 상속 프록시에서 403을 받았습니다. `--ignore-health-check`로 로컬 서비스를 유지한 뒤 loopback Auth·메일 API와 실제 동작으로 검증했습니다. 이 옵션은 TLS/서명/체크섬 검증을 끄지 않습니다.
- 프로덕션 빌드는 기존 `next/font/google`의 Google Fonts 접근 차단으로 실패합니다. 도메인 허용 후 다시 빌드해야 하며, 빌드 성공·운영 배포를 주장하지 않습니다.

최초 회원 연결에서 아직 클라우드 스냅샷을 받지 못했다면 빈 날짜를 확정하거나 회원 편집을 허용하지 않습니다. 한 번 동기화된 캐시는 이후 오프라인 편집을 지원하며, 첫 연결 실패 중에도 비회원 모드를 사용할 수 있습니다. CI에는 비회원 회귀와 별도 로컬 Supabase 통합 job을 포함합니다.
