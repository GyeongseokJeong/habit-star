# V5 별빛 카드 — SNS 공유 디자인 및 구현 범위

## 확정된 사용자 흐름

메인 별자리 티저 → 별자리 성장 상세 → **별빛 카드 만들기** → **4:5 미리보기** → (다음 단계) PNG 저장·공유. 메인에 별도 CTA를 추가하지 않는다.

## 디자인 확정 규칙 (V5 디자인 보정)

- **카드 자체**는 4:5 (다음 단계 1080×1350 PNG 목표). 모달의 뒤로가기/닫기/주변 UI는 이미지에 포함하지 않는다.
- 실제 기록에서 계산한 현재 획득 Stage, 연속 실천일, 누적 실천 횟수를 사용한다. 이전 Stage 갤러리 탐색은 공유 카드의 Stage를 바꾸지 않는다.
- 승인된 Stage 1~6 **2:3 원화는 픽셀 변경·왜곡·크롭 없이 전경에서 `object-contain`으로 표시**한다.
- 동일한 원화를 흐린 저투명도 **장식용 배경**으로 재사용할 수 있다. 배경은 흐림/일부 잘림이 가능하지만 원본 파일 자체를 변형하거나 승인 원화를 대체하지 않는다.
- 상단 브랜드는 **별하루 / BYEOLHARU 단 한 번**. 기존 감성 문구는 유지.
- Stage 작품명은 원화 아래 한 번. **Stage 번호는 세 번째 지표에서만 한 번** 보여 중복을 없앤다.
- 하단은 **연속 실천 / 누적 실천 / 현재 단계** 세 지표만 유지한다.
- 테두리·배경 빛은 차분한 네이비·퍼플·골드; 과한 외곽 네온 및 불필요한 설명 문구·중복 로고는 제거.
- 계정 식별 정보, 습관 제목, 별점 기록 상세는 기본 공유 이미지에 넣지 않는다.
- 앱 라이트/다크 테마와 별개로, 이미지의 브랜드 밤하늘 배경은 동일하게 유지한다.

## 구현 단계

1. **디자인 보정 (현재 PR)**: 원화 확대, 흐린 보조 배경, 중복 제거, 4:5/모바일/Stage/접근성 회귀. 데이터 변경 없음.
2. **PNG 저장 (현재 STEP 2 PR)**: 미리보기와 동일한 DOM 카드만 1080×1350 PNG로 내보낸다. 명시적 버튼을 눌렀을 때만 html-to-image 모듈을 로드하고 한국어 글꼴·원화 이미지 로딩 후 렌더한다. PNG 헤더/가로세로 규격을 검사하고, 오류에는 재시도를 안내한다. 저장 버튼·모달은 출력에서 제외한다. 브라우저 다운로드는 지원하되 Android WebView의 실제 파일 저장 경로는 실기기 검증이 필요하다.
3. **공유 (STEP 3 PR)**: 별빛 카드 PNG가 준비되면 파일 공유 가능 여부를 `navigator.canShare({ files: [File] })`로 확인하고, **사용자가 이미지 공유를 누른 동기적 클릭 경로에서** `navigator.share(...)`를 호출한다. 준비 중은 비활성화, 사용자 취소(AbortError)는 조용히 처리하고, 미지원 브라우저·Android WebView에서는 PNG 저장으로 안내한다. PNG 캡처는 기존 STEP 2 함수를 재사용하고, 저장·공유 컨트롤은 카드 출력에 포함하지 않는다. Instagram/Kakao의 수신·업로드 동작과 Android WebView 공유 브리지는 **별도 실기기 검증 대상**이며 자동 게시를 지원한다고 주장하지 않는다.
4. **공유 품질 마무리 (V5 STEP 4)**: 자동 E2E로 모바일 공유 API 호출 시 사용자 활성화, 공유 취소 처리, 저장한 PNG와 공유한 파일의 **바이트 단위 SHA-256 일치**, PNG 1080×1350 규격을 검증한다. 카드 디자인·기록·원화는 변경하지 않는다.
5. **실기기·SNS 검증 (수동)**: 320/390/430px, 라이트/다크, 320px 축소 가독성, 한국어 폰트, 4:5 출력 비율, 인스타그램 피드/카카오톡 이미지 수신 후 실제 크롭·미리보기·텍스트 확인. 자동 E2E만으로 각 SNS 업로드 완료를 보장하지 않는다.

## 인스타그램 공유 동작: 확인된 한계 및 안전한 경로

- **관찰**: Android 실기기에서 별빛 카드의 시스템 공유 시트를 통해 인스타그램을 선택하면 앱은 실행되지만 피드 편집 화면이 열리지 않는 경우가 있다. 같은 사용자 환경에서도 정상 편집 화면으로 연결되는 경우가 있다.
- **현재 진단**: 별하루는 `navigator.share({files: [pngFile], title: ...})`로 PNG 파일을 OS 공유 시스템에 전달한다. Web Share API의 성공은 **대상 앱으로의 전달**을 의미하며 인스타그램 내부의 피드 편집/게시 성공을 보장하지 않는다. 별하루 웹 코드로 인스타그램의 내부 피드 화면을 강제할 수 없다. 정확한 실패 원인은 아직 확정하지 않는다.
- **확실한 대안 안내**: **별빛 카드 → 이미지 저장 → 인스타그램 앱 실행 → + → 게시물 → 저장한 PNG 선택**. 이 경로로도 실패하는지 비교하면 수신 앱 문제와 Web Share 경로 문제를 구분하는 데 도움이 된다.
- **재현 진단 업데이트 (2026-11-21)**: 동일한 PNG로 (A) 별하루의 이미지 공유 → 인스타그램, (B) Android 갤러리/내 파일에서 공유 → 인스타그램을 비교한 실기기 결과, **A와 B에서 동일한 간헐적 실패가 나타남**. 별하루만의 Web Share 구현 문제일 개연성은 낮아졌으나 Instagram/Android 공유 수신 경로와 파일 인코딩·해석 문제는 아직 구분되지 않는다. (C) 인스타그램 앱의 + → 게시물에서 직접 선택은 미검증으로 남겨둔다. 피드/스토리 공유 대상 선택, 브라우저·앱 환경, 인스타그램 버전, 성공·실패를 기록한다.
- **릴리스 기준**: 카카오톡 전송·공유 취소 및 **이미지 저장 경로**는 유지하고, 인스타그램 피드 편집 자동 진입은 **미보장/추가 검증**으로 명시한다. 인스타그램 진입 실패를 사용자가 취소한 것으로 처리하거나 게시 성공이라고 표시하지 않는다. 서드파티 앱 내부 동작을 강제하는 비공식 딥링크/컴포넌트명은 사용하지 않는다.
- **후속 판단**: 수신 앱/플랫폼 구분 없이 Web Share 연결이 반복 실패한다는 재현 증거가 나오기 전에는 이미 통과한 카카오톡 공유 동작을 위험하게 바꾸지 않는다.

본 문서의 화면 규칙은 Stage 원화/습관 기록/동기화 정책을 변경하지 않는다.
