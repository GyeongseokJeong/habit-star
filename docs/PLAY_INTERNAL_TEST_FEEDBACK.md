# Play 내부 테스트 — 피드백 및 최소 이용 지표 (#200)

기준: main `ab40fbc7` (#236), Android 0.1.1 / versionCode 2 후보. 이 문서는 **내부 테스트 운영·지표 정의 제안**이다. 실제 Play 등록 최고 코드, 서명·업로드, 표준 Release 실기기 인수, 외부 백업·격리 복원은 미확인/미완료다. 테스트 참가자 모집, 연락, 설문 발송, 신규 이벤트·SDK·운영 조회/저장 및 공개 배포는 수행하지 않는다. #200은 정책 승인과 실제 피드백 검증 전까지 열어 둔다.

## 1. 내부 테스트 시작 조건 및 출시 노트 초안

- [STEP 4F](WIDGET_RELEASE_ENABLED.md)의 F01~F05를 기준으로 Play 최고 사용 versionCode 확인 → main 보호 워크플로 서명 → 내부 테스트 트랙 업로드 → 실제 Play 설치/업데이트 및 인수. 기존 Play 설치본은 삭제하지 않는다. 같은 서명이 확인된 이전 Play 설치본이 없으면 업데이트 검증은 BLOCKED로 둔다.
- PR #236의 자동 검증과 #235의 소유자 보고(위젯 완료, 알림 취소, 완료 취소 후 재예약, offline→online 동기화 4/4)는 기존 근거다. 일반 Release/Play 설치에서의 결과는 별도 수집한다. 아래 QA는 모두 NOT RUN.
- Play 내부 테스트용 한국어 출시 노트 초안(실제 업로드 전에 현재 후보와 일치 확인):

> 홈 화면 위젯에서 오늘의 습관을 완료하거나 완료를 취소할 수 있어요.
> 위젯 완료 상태에 맞춰 습관 알림 예약을 조정하고, 기존 기록과 동기화 흐름을 유지하도록 개선했어요.

OS 강제 중지, 절전, 권한에 관계없이 알림/동기화가 즉시 보장된다는 문구는 쓰지 않는다. 내부 테스트와 공개 출시는 별도이며 공개 출시 승인 전 F01~F05, #147, #160, #188 등 필수 게이트 확인.

## 2. 실제 테스터용 과제 (승인 후, 가상 습관 및 격리된 테스트 계정만)

목표는 설치→첫 실천의 마찰, 바쁜 일상에서 위젯을 통한 빠른 기록, 권한/네트워크 변화 뒤 기록 신뢰를 검증하는 것이다. 새 설치 비회원 A, 기존 Play 설치/반복 사용 B, 격리 회원·다기기 C, 큰 글자·TalkBack D의 환경을 포함한다. 실제 참여 수, OS/런처·설치 경로의 분포 및 결측을 집계한다. 해당 환경 참가자가 없으면 미검증이지 성공이 아니다. 소수 자발적 테스터의 결과는 시장 전체로 일반화하지 않는다.

| ID | 수행 과제 | 판정 조건 / 상세 인수 기준 |
| --- | --- | --- |
| T01 P1 | 별하루를 Play에서 설치하고 첫 실제 테스트 습관을 만든 뒤 실천을 기록 | 예시 습관과 실제 기록 구분, 첫 저장 후 앱 재진입에도 보존 |
| T02 P1 | 위젯을 설정한 후 최근 앱 목록에서 별하루 제거 → 위젯으로 완료 → 예정된 시각까지 앱을 다시 열지 않기 | 완료 표시와 원본 일치, 완료한 습관의 알림은 발생하지 않고 별도로 예약한 다른 습관 알림은 유지 |
| T03 P1 | 별도의 미래 예정 습관을 위젯에서 완료했다가 취소 → 앱을 열지 않고 예정 시각 관찰 | 취소가 원본에 반영되고 재예약 알림 실제 수신. T02와 구별해 수행 |

| T06 P1/P2 | 첫 알림 안내의 허용/나중에/거부/재허용, 정확 알림 차단 및 실제 알림 탭 | [권한 및 #188 알림 상세 인수](ANDROID_NOTIFICATION_FIRST_PERMISSION_TEST.md) 기준; 권한 자동 강제 이동·데이터 변경 금지 |
| T07 P1/P2 | 동일 Play 서명의 이전 버전→후보 업데이트(별도 신규 설치와 구분), 재부팅/절전 및 큰 글자·양 테마/위젯 resize | 기존 기록·설정·회원 및 위젯 보존, F04 기준. 기존 설치본을 지우거나 실데이터 초기화하지 않음 |
| T08 연구 | 이용자가 원할 때 별빛 카드 공유를 시도하고 다음 방문 이유/어려움을 설명 | 공유 시도와 실제 SNS 게시 구분. 게시 강요·실제 개인정보 제출 없음 |

T01~T08의 축약 과제는 F02~F05, B/R 케이스 등 원래의 상세 필수 QA를 대체하지 않는다. OS 설정의 '강제 중지'는 최근 앱 제거와 다른 환경으로 기록한다. 오류 시 원본과 증거를 보존하고 중복 터치·무단 삭제/복구하지 않는다.

### 피드백 양식 (공유 전 소유자 검토)

- 후보 build-info의 버전·versionCode·SHA, 설치 유형(Play 신규/동일 Play 서명 업데이트/테스트 APK), 기종·Android 버전·런처·WebView 버전(알 수 있는 경우), 앱 테마/권한/온라인 상태.
- 과제 ID / 조작 순서(가상 습관만) / 기대 결과 / 실제 결과 / PASS·FAIL·NOT RUN·BLOCKED / 재현 여부(한 번/반복/미확인).
- 중립 질문: “무엇을 하려고 했나요?”, “어디서 멈추거나 예상과 달랐나요?”, “다시 사용할 때 불편할 것 같았던 점은 무엇인가요?”
- 선택사항: 별빛 카드 공유를 시도했는지(예/아니오/미응답). 실제 게시 링크·수신자 정보는 받지 않는다.
- 이메일, 실제 습관명·메모, 계정 ID, 토큰·비밀번호, 원본 백업, 사용자 정보가 포함된 화면/로그는 제출하지 않는다. 화면 증거가 필요할 때는 가상 데이터로 재현하고 가려야 할 정보가 없는지 확인한다.
- 승인된 피드백 원본은 운영자가 제한된 범위에서 검토하며 GitHub에는 개인별 원문이 아닌 마스킹된 결함·재현 조건·집계만 남긴다. 제안: 검토 완료 후 원본 30일 이내 삭제, 소규모 코호트 재식별 가능성이 있는 세부 조합 비공개. 실제 보관 위치·삭제/철회 방법·고지 내용은 수집 전에 확정한다.

## 3. 최소 지표 정의 — 계측 없는 1차 제안

**현 상태: 실측 없음(N/E).** 별도 추적 SDK/자동 heartbeat/운영 DB 조회/계정 연결을 도입하지 않는다. 내부 테스트에서 사전 동의한 자발적 응답의 집계만 제안한다. 이는 제품 전체 이용자 통계가 아니라 소규모 테스터 자가 보고이며 Play 설치 수·앱 실행 수와 실천 수를 혼동하지 않는다.

공통 분모 및 기간: 버전별로 테스트 시작일(자발적 첫 사용 보고, KST 달력 날짜)을 D0으로 정의한다. 동의한 신규 테스트 참가자 1명당 1회, 추가 기기·재설치·계정 전환이 새로운 참여자로 계산되지 않도록 중복을 확인한다(계정·기기 ID 수집 금지). 기존 이용자/업데이트는 별도 코호트로 구분한다. 실제 완료 기록(`completed=true`, 별점 0 포함)의 **저장 성공**만 실천으로 정의하고 샘플·중복 탭·실패·같은 날 취소된 최종 기록을 제외한다. 과거 날짜 입력/수정, 오프라인 재동기화는 실제 실천 날짜 기준이며 측정 창 종료 7일 안에 도착한 확정 상태를 집계한다. 이 정의에 대한 응답이 불명확하면 결측으로 표기한다. 아래 항목은 개인 원문이나 기록 수집이 아닌 참가자의 자발적 예/아니오·일수 자기보고에 한한다.

| 지표 | 분자 / 분모와 관측 창 | 제품 결정 |
| --- | --- | --- |
| 첫 실천 | D0 당일(D1 시작 전까지) 실제 첫 실천 완료 보고자 / D0 관측이 종료된 신규 참가자 중 유효 응답자 | 첫 화면·습관 생성 및 기록 마찰 점검 |
| D7 실천 유지 | D7 당일 적어도 1회 실천한 신규 참가자 / D7 종료 후 유효 응답한 신규 참가자 | 1주 뒤 습관 재개/위젯·알림 경험 점검 |
| D30 실천 유지 | D30 당일 적어도 1회 실천한 신규 참가자 / D30 종료 후 유효 응답한 신규 참가자 | 장기 가치 가설 검토; 짧은 내부 테스트에서는 N/E |
| 첫 주 실천일 | D0~D6 중 적어도 1회 실천한 날짜 수(0~7)의 합 / 7일 전체 유효 응답 참가자 수 | 실제 사용 빈도 및 쉬었다 돌아오는 경험 점검 |
| 첫 주 공유 시도 | D0~D6 실제 별빛 카드 공유 UI 시도 1회 이상 보고자 / 7일 전체 유효 응답 참가자 | 자발적 공유 관심 확인; SNS 게시/유입/성공 전환 아님 |

D7/D30은 **실천 유지율**로 정의한다(앱 방문 리텐션 아님). 단순 앱 열기·푸시 수신·위젯 렌더링은 해당 지표의 성공으로 세지 않는다. 동의 철회 시 식별 가능한 응답 제거, 중복 가능/미성숙 코호트/미응답을 성공 또는 실패로 강제 분류하지 않는다. 각 항목에 eligible N, 유효 응답 n, 결측 N−n, 분자, n/N을 함께 표시한다. n=0은 N/E; 관측 응답률이 낮으면 비응답 편향을 명기하고 수치로 출시·수익화 결정을 하지 않는다. 첫 캘린더 날짜가 짧아지는 편향, 자기보고 기억·선택 편향 및 버전/기기 차이는 결과마다 기록한다.

**합성 예시(실측 아님):** D7 대상 10명 중 응답 6명, 실천 4명, 미응답 4명이라면 응답자 중 4/6 (66.7%), 응답률 6/10 (60%), 대상 전체에서 가능한 범위 4/10~8/10이다. 미응답을 0으로 입력하면 왜곡된다.

향후 자동 계측이 필요해도 현재는 구현하지 않는다. 목적·최소 이벤트/중복 제거·동의 철회·보관·삭제·접근 제어·오프라인/다기기 경계·스토어 Data Safety와 실제 동작 일치 여부를 별도 승인한 뒤, 별도 PR 및 격리 테스트에서 검증한다. 기록 자체·성장 정책이나 인증/동기화 경로를 지표를 위해 수정하지 않는다.

## 4. 판정·후속 작업

- P0(기록 유실/타 계정 노출/치명적 장애) 또는 P1(핵심 기록·알림·업데이트 및 필수 권한/접근성 실패) 확인 시 해당 테스트 진행을 중단하고 마스킹한 증거를 보존하여 결함 PR 및 동일 조건 재검증. 문제 해결 전 공개 출시 금지. 미실행 필수 P0/P1 검사도 통과로 선언하지 않는다.
- P2/P3 의견은 영향/관측 빈도·회복 가능성·실제 증거를 바탕으로 정리. 첫 실천/리텐션 지표의 기준선이 없으므로 근거 없는 합격률/목표 수치 또는 통계적 효과를 주장하지 않는다.
- 승인 후 실제로 실시한 과제의 대상 SHA, 환경, 실행 수, PASS/FAIL/NOT RUN/BLOCKED, 증거 링크 및 재검증 결과를 기록. #189 위젯, #160 권한, #188 알림 이동과 연결하고 #147 외부 백업/격리 복원 게이트를 유지한다.
- #200 완료: 소유자 정책 검토·승인 → 실제 내부 테스터 피드백/승인된 최소 집계 검증(계측 필요 시 별도 승인/PR) → CI/실기기 검증 및 PM 확인. 이 문서만으로 완료 또는 출시 가능 처리하지 않는다.

## 5. 관점 검토 (동일 모델 2회, 실제 전문가·참가자 조사 아님)

release + android + research + analytics. PM/BM/마케팅/사용자, 운영/QA/Android/보안, 리서치/제품 분석. 보호 스킬 release-guardian/quality-gate. 실제 증거 부족으로 사용자 행동·지표 실측·Play 업데이트·권한 분기·공개 출시 게이트는 N/E이며 역할 종합 점수를 만들지 않는다.
