# 회원 탈퇴 — 구현 및 출시 게이트

## 확정 동작
- 내 계정 최하단에 개인정보처리방침 텍스트 링크를 유지한다. 정책 본문에는 탈퇴 경로와 이메일 문의를 안내하며 별도 삭제 버튼은 두지 않는다. Play Console에는 공개 `/privacy` 및 `/account-deletion` URL을 등록한다. 공개 삭제 요청 페이지의 로그인 및 이메일 요청 경로와 정책 페이지 하단 링크를 유지한다.
- 로그인 회원: 내 계정 → 계정 관리 → 회원 탈퇴. 삭제 대상·복구 불가·백업 안내, 현재 비밀번호, 명시적 동의 후 서버가 삭제한다. 로그인 불가 이용자만 공개 웹 안내의 이메일 문의를 이용한다.
- `delete-account` Supabase Edge Function: 사용자 JWT를 Auth 서버에서 검증하고, 토큰에서 확인된 이메일과 비밀번호로 재인증한다. 재인증 ID가 같아야 Auth admin hard-delete를 실행한다. 요청의 사용자 ID를 신뢰하지 않으며 서비스 키는 함수 내부에서만 사용한다. 계정이 없거나 미확인/비밀번호 불일치/실패하면 삭제 성공 응답을 보내지 않는다.
- 성공한 계정의 서버 자료와 인증 세션은 cascade한다. 기존 `private.owner()` 검증으로 삭제된 JWT가 재생성하지 못하게 한다. 현재 기기의 회원 IndexedDB scope 및 계정별 마무리 알림/진단 캐시만 지우고, 비회원/다른 회원/내보낸 파일은 보존한다. 다른 기기 오프라인 사본 및 외부 공유 파일은 직접 관리가 필요하다. 다른 기기의 인증·서버 접근은 삭제 후 거부된다.
- 네트워크 실패나 응답 유실만으로 로컬 원본을 버리지 않는다. 서버 삭제 성공이 확인된 경우에만 로컬 정리를 실행하고, 로컬 처리 실패와 서버 삭제 성공을 구분한다.

## 출시 순서 (운영 변경은 별도 승인)
1. CI verify / cloud 및 Android 빌드 확인. 마이그레이션 `20261128034737_account_deletion_integrity.sql`의 운영 적용 여부·전체 계정 FK 및 기존 토큰 차단을 확인한다. **미적용이면 함수 배포 금지.** 이전 마이그레이션 재실행/DB reset 금지.
2. 운영 적용 이력/백업·복구 검토 후 `delete-account` 함수를 대상 프로젝트에 배포한다. Supabase CLI 명령 예: `pnpm exec supabase functions deploy delete-account --project-ref <정확한-project-ref> --no-verify-jwt`. 함수가 직접 Auth 서버를 검증하므로 gateway의 구형 JWT 검증을 사용하지 않는다. 서비스 키를 앱/웹 환경변수로 추가하지 않는다. 운영 Auth 비밀번호 로그인 보호/속도 제한 확인.
3. 공개 웹 배포 및 다음 Android versionCode의 서명 AAB로 검증한다. 이메일 요청은 로그인할 수 없는 경우에만 지원 경로로 유지. Play Data safety 선언 및 공개 URL이 실제 동작과 일치해야 한다.
4. 실기기에서는 테스트 전용 계정으로 동의 체크 전 차단, 취소/오류에서 보존, 백업, 성공 후 비회원/회원 캐시 정리, 위젯 전환 및 이전 계정 알림 취소, 기존 비회원 데이터 보존, 재로그인 거부를 확인한다. 실제 사용자 계정은 테스트하지 않는다.

## 하네스 검토 (동일 모델의 구조화된 관점 검토, 실사용자 조사 아님)
- Route: new-feature + ui + data + implementation + security. PM/UI/UX/사용자/아키텍트/클린코드/풀스택/QA/보안.
- 1차: 메일 전용 UX의 운영 의존성과 정책 링크 가시성을 검토. 독립 대형 메뉴 대신 하단 정책 링크 유지, 직접 탈퇴는 계정 관리로 이동. 단순 session-only 삭제에 대해 세션 탈취 반례를 수용해 비밀번호 재확인, 계정 ID 일치, 삭제 동의, 백업 선택 추가.
- 2차: 삭제 후 로컬 캐시·동시 동기화/과거 JWT·다른 계정 영향, 연결 끊김 및 운영 migration 누락 반례를 검토. 기존 FK cascade/owner 잠금, 성공 확인 후 범위별 캐시 삭제, 실패 보존, 정확한 토큰 고정, 출시 전 운영 마이그레이션 게이트 및 로컬 실통합 테스트로 수정. 변경 범위의 주요 이견은 해소. 실제 운영 배포 및 Android 실기기 검증은 별도 게이트로 남김.
- 자동 검증: 핸들러 메서드/인증/비밀번호/위조 사용자/실패, 기기별 키 격리, 공개 페이지 및 게스트 경로, local Supabase 실제 Edge Function으로 UI 탈퇴와 stale JWT/다른 계정 불변, 기본 SQL 계정 삭제 테스트. CI로 실제 검증한다.

## 계정 관리 화면 디자인 검토 (추가 마감)
- Account Design System v1: 14px 섹션 제목, 14px 공통 카드, 44px 이상 조작 영역, 덮어쓰지 않는 기존 테마 토큰.
- 로그인 정보는 긴 이메일을 줄바꿈하는 독립 카드로 정리하고, 로그아웃은 중립 보조 버튼, 회원 탈퇴는 별도 삭제 그룹과 위험 색·명시적 영구 삭제 문구로 구분한다. 정상 로그아웃에 불필요한 캐시 기술 설명을 노출하지 않고 미전송/충돌 경고만 유지한다.
- 탈퇴는 복구 불가 경고, 삭제 범위, 선택 백업, 현재 비밀번호·동의, 최종 삭제 버튼 순서. 비밀번호 길이 안내는 가입 화면에 유지하며 탈퇴 재인증에는 불필요하다. 비활성 버튼은 중립 표면·실제 disabled 상태로 표시한다.
- 320/390/430px, 라이트·다크의 계정 관리·탈퇴 화면, 터치 크기, 긴 이메일 줄바꿈, 위험 동작 위계를 기존 로컬 Supabase E2E에 추가. 실기기 외관은 별도 검증한다.
