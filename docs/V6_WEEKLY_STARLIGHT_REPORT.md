# V6 주간 별빛 리포트 — STEP 1: 읽기 전용 집계

## 목표

사용자가 지금까지 기록한 실제 실천을 바탕으로, 한 주(월요일~일요일)의 별빛을 부담 없이 돌아볼 수 있는 기능을 준비한다. 첫 단계는 **UI 없는 순수 집계 엔진**만 구현한다. 카드·모달·알림·기록 저장·DB 스키마는 변경하지 않는다.

## 집계 규칙

- **기준 날짜**: 현재 계정/기기의 로컬 날짜 키 `YYYY-MM-DD`. 시간대 변환을 엔진에서 다시 하지 않고 기존 앱이 확정한 날짜 키를 입력한다.
- **주간 범위**: 월요일 00:00~일요일 23:59에 해당하는 **날짜 키 7개**. `weeksAgo=0`은 이번 주, `1`은 지난주.
- **실천 건수**: 기존 `calculateConstellationGrowth`가 각 날짜별로 중복 제거한 `completedHabits` 합계. 별점 0이어도 명시적인 완료라면 인정한다.
- **별빛 점수**: 기존 성장 엔진의 일별 `points` 합계. 하루 최대 3점 정책을 다시 정의하지 않는다.
- **실천한 날**: 완료 습관이 하나 이상 확인된 날짜 수. `실천한 날 / 7일`을 습관 준수율이나 실패 지표로 표현하지 않는다.
- **오늘과 과거 중복**: 원본 성장 엔진에서 오늘 `habits`가 `history` 사본보다 우선한다.
- **미래 날짜**: 집계에서 제외하고 `isFuture`로 구별한다. 예정된 습관, 실패, 누락 등으로 추측하지 않는다.
- **기록 없는 날짜**: 0건·0점으로 표시하되 벌점·미실천 평가·기록 생성은 없다.
- **예시 습관 자동 완료**: 기존 V3.2 성장 계산의 예외 정책을 그대로 따른다.
- **범위**: 현재 로그인 계정/비회원의 이미 계산된 `ConstellationGrowth.days`만 사용한다. 다른 계정과 혼합하지 않고 상태를 저장하지 않는다.
- **미완성 주**: 해당 주 일요일이 지나기 전은 `isComplete=false`로 표시한다.

## 후속 개발 (미확정 UI)

- STEP 2: 승인된 별하루 시각 언어로 **간결한 주간 리포트** 시안 및 진입 위치 검토. 주간 별빛 합계, 실천한 날, 기록 캘린더 등은 과밀하지 않게 구성.
- STEP 3: 현재 계정·기기 날짜 기준 데이터 연결, 이전/다음 주 이동, 비어 있는 주의 감성적 빈 상태.

**중요**: 주간 리포트의 장려 문구·지표 디자인·진입 위치는 별도 승인 전까지 확정하지 않는다.


## STEP 2 — 화면 통합 제안 (2026-11-21, 디자인 검토용·미확정)

### 기존 구현을 확인한 결과

이미 달력 탭에는 `최근 7일 돌아보기` 진입 버튼과 `WeeklyReflectionView`가 있다. 이 기능은 **오늘을 제외한 최근 7개 날짜**의 확인 가능한 예정일·완료 이력에서 이어갈 습관을 제안한다. 새 V6 집계는 **이번 주 월요일~일요일**의 실천 횟수·별빛 점수·실천한 날을 보여주므로 목적과 기간이 다르다.

새로운 홈 카드·달력 탭 버튼·메인 메뉴를 만들면 두 개의 '주간' 진입점이 중복된다. 기존 돌아보기 진입 흐름을 재사용하고 **한 화면에서 서로 다른 기간을 명시**하는 안을 추천한다.

### 제안 A — 기존 돌아보기 화면 안에 소형 리포트 (추천)

- 기존 달력 탭에서 하나의 `돌아보기` 버튼으로 진입한다. 주간 별빛 리포트 전용 홈 CTA/별자리 갤러리 CTA는 만들지 않는다.
- 화면 제목: `나의 돌아보기`. 첫 섹션 `이번 주 별빛`은 실제 집계 기간 `11.16(월)–11.22(일)`과 함께 표시한다.
- 섹션 크기는 모바일 **약 150~190px 목표**. 수치 2개만 크게 표시: `실천 9회` / `모은 별빛 7점`. `4일 실천`은 작은 보조 텍스트로 표시한다. 예시는 목업이며 실제 숫자를 하드코딩하지 않는다.
- 하단에 `월 화 수 목 금 토 일` 7일 스트립을 둔다. 완료된 날짜는 별빛 아이콘/표식, 기록 없는 날짜는 중립적인 표시, 미래 날짜는 연한 `예정` 표식으로 구분한다. **기록 없음 ≠ 실패**. 모두 읽기 전용이며 요일 셀은 버튼이 아니다.
- 두 번째 섹션 `최근 7일의 흐름`에는 기존 `WeeklyReflectionView`의 추천/격려/기록하기 동작을 그대로 유지한다. 이 섹션의 기간은 반드시 **오늘 제외한 지난 7일**로 따로 표시하여 '이번 주'와 혼동되지 않게 한다.
- 기존 사용자가 동작에 익숙한 `오늘 기록하기`, `달력으로`, 닫기/복귀 초점, 다크/라이트 톤은 그대로 유지한다.
- 비회원/로그인 회원의 빈 기록에는 `이번 주의 별빛은 아직 조용해요.` 등 짧은 중립 문구로 충분하다. 성공률·스트릭 압박·추측 퍼센트·실패 판정은 추가하지 않는다.
- 주간 이미지 내보내기, 알림, 별자리 Stage 이미지 반복, 계정 데이터 쓰기는 포함하지 않는다.

### 제안 B — 달력 아래 별도 주간 카드 (비추천)

- 달력 탭 자체에 이번 주 요약을 추가하고 기존 `최근 7일 돌아보기` 버튼은 별도로 둔다.
- 장점은 탭에서 요약을 바로 볼 수 있다는 점. 단점은 달력 하단이 길어지고, **비슷한 '주간' 정보가 두 군데** 나타나며 메인 기록 흐름이 무거워진다는 점.

### 문자 와이어프레임 (실제 디자인 아트 아님)

```text
← 나의 돌아보기

  ✦ 이번 주 별빛              11.16 – 11.22
      실천 9회       모은 별빛 7점
                 4일 실천
      월   화   수   목   금   토   일
      ✦    ·    ✦    ✦    ·    ✦    …

  최근 7일의 흐름            11.14 – 11.20
  [기존 돌아보기의 짧은 격려 또는 다시 이어갈 습관]
  [기존 오늘 기록하기 동작 그대로]
```

### STEP 3 구현 전 승인·검증 조건

- **UI 명칭/배치/밀도는 승인 전까지 미확정**. 이 PR은 계획 문서 외 코드를 변경하지 않는다.
- STEP 3에서 기존 `WeeklyReflectionView` 재사용 우선. 기존 월간 매트릭스·첫 방문 안내·메인 Stage·Android 영역은 건드리지 않는다.
- 기기별 320/390/430px, 라이트·다크·글자 확대, 이번 주 중간/일요일/지난 주 경계, 데이터 없음, 로컬/회원 계정 분리, 뒤로가기·키보드 초점을 검증한다.
- 실제 카피는 감성 최소주의를 준수하고, 실천이 없던 날에 잘못을 의미하는 색·표정을 사용하지 않는다.
