# V6 주간 별빛 리포트 — STEP 1: 읽기 전용 집계

## 목표

사용자가 지금까지 기록한 실제 실천을 바탕으로, 한 주(월요일~일요일)의 별빛을 부담 없이 돌아볼 수 있는 기능을 준비한다. 첫 단계는 **UI 없는 순수 집계 엔진**만 구현한다. 카드·모달·알림·기록 저장·DB 스키마는 변경하지 않는다.

## 집계 규칙

- **기준 날짜**: 현재 계정/기기의 로컬 날짜 키 `YYYY-MM-DD`. 시간대 변환을 엔진에서 다시 하지 않고 기존 앱이 확정한 날짜 키를 입력한다.
- **주간 범위**: 월요일 00:00~일요일 23:59에 해당하는 **날짜 키 7개**. `weeksAgo=0`은 이번 주, `1`은 지난주.
- **실천 건수**: 기존 `calculateConstellationGrowth`가 각 날짜별로 중복 제거한 `completedHabits` 합계. 별점 0이어도 명시적인 완료라면 인정한다.
- **별빛 점수**: 기존 성장 엔진의 일별 `points` 합계. 하루 최대 3점 정책을 다시 정의하지 않는다.
- **실천한 날**: 완료 습관이 하나 이상 확인된 날짜 수. `실천한 날 / 7일`을 습관 준수율이나 실패 지표로 표현하지 않는다.
- **오늘과 과거 중복**: 원본 성장 엔진에서 오늘 `habits`가 `history` 사본보다 우선한다.
- **미래 날짜**: 집계에서 제외하고 `isFuture`로 구별한다. 예정된 습관, 실패, 누락 등으로 추측하지 않는다.
- **기록 없는 날짜**: 0건·0점으로 표시하되 벌점·미실천 평가·기록 생성은 없다.
- **예시 습관 자동 완료**: 기존 V3.2 성장 계산의 예외 정책을 그대로 따른다.
- **범위**: 현재 로그인 계정/비회원의 이미 계산된 `ConstellationGrowth.days`만 사용한다. 다른 계정과 혼합하지 않고 상태를 저장하지 않는다.
- **미완성 주**: 해당 주 일요일이 지나기 전은 `isComplete=false`로 표시한다.

## 후속 개발 (미확정 UI)

- STEP 2: 승인된 별하루 시각 언어로 **간결한 주간 리포트** 시안 및 진입 위치 검토. 주간 별빛 합계, 실천한 날, 기록 캘린더 등은 과밀하지 않게 구성.
- STEP 3: 현재 계정·기기 날짜 기준 데이터 연결, 이전/다음 주 이동, 비어 있는 주의 감성적 빈 상태.
- STEP 4: 모바일·라이트/다크·시간대·오프라인·데이터 정합성 검증. SNS 공유 카드와 기능을 무조건 결합하지 않는다.
