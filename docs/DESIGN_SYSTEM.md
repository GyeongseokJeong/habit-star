## Android 앱 설정 상용화 정리 — 2026-11-23

- Android 앱 설정은 '알림 → 화면 → 기록' 그룹으로 정리한다. 기기 알림 상태·필요한 조치, 아침/낮/밤 마무리 알림 3개, 화면 테마·간편 보기, 기록 시간대, 접힌 앱 정보를 표시한다.
- '알림 문제 해결' 개발자용 UI(예약 수 조회/예약 비교/수동 복구 및 내부 진단 로그)는 **일반 사용자 화면에서 제거**한다. 네이티브 예약 감사·복구 엔진과 테스트는 삭제하지 않는다. 자동 재예약/권한 복구는 기존 동작을 유지한다.

- 마무리 알림 OFF는 시간 선택 컨트롤을 숨기고 ON 상태에서만 노출한다. 시간대 반복 범위·최대 예약 수 등 구현 세부사항 대신 알기 쉬운 켜짐/꺼짐·시간을 보여준다.
- 마스터 알림 토글 추가, 기존 개별 습관/마무리 설정값 자동 수정, Supabase/DB/Outbox 변경, 화면 영역 밖의 디자인 개편은 하지 않는다. Android/Web 공통 페이지에서 Android 관련 항목은 네이티브 prop이 있을 때만 표시한다.
- 320/390/430px 및 라이트·다크 실기기 검증이 완료되기 전에는 최종 상용화 UI 품질을 승인하지 않는다.

## Android 시간대 마무리 알림 V1 — 사용자 승인 (2026-11-22)

- Android 앱 설정에 **아침·낮·밤 각각 독립적인 ON/OFF**와 시간 선택을 표시한다. 별도 전체 마스터 토글은 없다. 기본값 모두 OFF, 권한 요청은 직접 켤 때만 하며 사용자 동의 없이 알림을 늘리지 않는다.

## 완료 상태 카드 통일과 전체 보기 안내 — 사용자 확정 (2026-11-22)

## 시간대 집중형 루틴 — 사용자 확정 (2026-11-21)

- 용어는 **습관 = 개별 등록 항목**, **루틴 = 시간대별 습관 묶음**, **실천 = 실제로 수행한 행동**, **기록 = 수행 결과**로 구분한다. 홈의 전체 제목은 '오늘의 습관', 상단 통계는 '오늘의 실천', 시간대 제목은 '나의 아침/낮/밤 루틴'이다.
- 아침·낮·밤 탭은 **선택한 시간대의 오늘 예정 습관만** 보여준다. 과거의 'UP NEXT' / 다음 시간대 미리보기 카드는 세 탭에서 모두 제거한다. 전체 탭은 오늘 예정된 모든 습관을 그대로 보여준다.
- 현재 시간대의 미완료 습관이 **0개**이고 **실제로 지난 시간대**에 아직 완료하지 않은, 오늘 예정된 습관이 있으면 작은 한 줄 안내를 보여준다: '다른 시간대에 남은 습관 N개 · 전체 보기'. 버튼을 누르면 전체 탭으로 이동한다. 다음 시간대는 포함하지 않으며, **00:00~04:59의 밤 탭에서는 당일 아침·낮 습관을 미완료로 간주하지 않는다.**
- 현재 시간대에 미완료가 남아 있거나, 이전 시간대의 미완료가 없거나, 전체 습관을 완료한 경우 안내를 숨긴다. 습관 카드 재노출/중복 CTA/경고색·부담을 주는 문구는 피한다.
- 기본·간편 보기에 동일한 조건을 적용하고, 320/390/430px·라이트/다크·화면 이동/키보드 접근을 확인한다. 완료 항목 접기/정렬 지연·기존 빈 시간대 및 쉬는 요일 안내는 유지한다.
- 사용자 기록, 요일·날짜별 저장, 회원 동기화, Android 알림 예약/권한, 별자리 점수와 푸터는 변경하지 않는다. 이 확정 정책은 아래의 과거 다음 루틴 미리보기 유지 정책보다 우선한다.

## V5.3 초기 예시 간소화와 일괄 정리 (2026-11-21)

- 완전히 새로 시작하는 비회원은 기본 예시 습관을 5개에서 2개(아침의 완료 예시 1개, 밤의 미완료 예시 1개)로 줄인다. 별점·완료 목록을 체험할 수 있지만 초기 정리 부담은 낮춘다.
- 기존 브라우저에 이미 생성된 예시 5개를 자동 삭제하거나 소급 변경하지 않는다. 기존 사용자 기록·복구본·클라우드 회원 습관에 영향을 주지 않는다.
- 비회원의 원본 시드 식별자(migration.entities)로 현재 남은 예시만 골라 '예시 한 번에 정리'를 보여준다. 예시 제목·순서·아이콘으로 탐지하지 않고 사용자가 직접 만든 습관은 제외한다.
- 정리 전 확인을 받고 성공 후 새로고침에서도 예시 정의가 나타나지 않는다. 습관 삭제의 기존 정책대로 과거 날짜 기록을 보존하며, 과거의 예시 실천 기록까지 일괄 삭제하는 DB 초기화 동작은 제공하지 않는다.
- 초기 시드와 기존 회원의 서명/동기화/계정 상태, 백업·복원·과거 기록·성장 계산은 유지하고, 정리 실패 시 사용자에게 재시도를 알린다.
- 모바일 320/390/430px과 일반·간편보기, 직접 만든 습관 보존, 취소, 재방문 회귀 검증을 추가한다.

## V5.2 첫 주 재방문 — 쉬는 요일/빈 탭의 정확한 안내 (2026-11-21)

- 등록된 습관은 계속 보존한다. 오늘 예정된 습관이 0개라도 신규 사용자처럼 '첫 습관 추가하기' 버튼을 표시하지 않는다.
- 모든 습관이 오늘 쉬는 요일이면 '오늘은 루틴 쉬는 날이에요'와 반복 요일에 다시 나타난다는 짧은 안내를 보여준다. 이 상황을 기록 삭제나 동기화 오류처럼 표현하지 않는다.
- 특정 시간대만 비었지만 오늘 다른 시간대에 예정 습관이 있으면 해당 시간대에 습관이 없음을 알리고 기존 '전체' 탭으로 돌아가는 버튼을 제공한다.

## 선택 및 테마 규칙

신규 선택형 버튼·탭·요일은 미선택일 때 중립적인 `--control-bg`, 선택 시 `--selection-bg`와 `--selection-fg`로 즉시 구별한다. 선택은 굵기·경계 또는 체크 표시로도 드러내고 `aria-pressed`(탭은 `aria-selected`), 키보드 포커스와 최소 44×44 CSS px 터치를 보장한다. 프리셋의 선택 여부는 현재 월~일 집합과 정확히 일치할 때만 참이다. 이모지와 별점은 고유 색을 유지한다. 설명 문구나 범례로 모호한 상태를 보완하지 않는다.

앱의 명시적 라이트·다크 테마가 OS 선호보다 우선한다. `.byeolharu`에 각각 명시적 `color-scheme`과 토큰을 적용하고 하위 `<dialog>` 및 네이티브 입력이 이를 상속한다. 테마 변경은 입력·선택 상태를 재생성하지 않는다. Android 브라우저의 강제 다크 모드는 별도 실기기 검증 대상이며 CSS만으로 통제된다고 가정하지 않는다.

### 브라우저별 색상 호환성

OS 테마, 브라우저의 웹페이지 강제 다크 모드, 별하루 앱 테마를 각각 식별한 뒤 표시 결과를 비교한다. 특정 브라우저의 색상 변환을 Starlit Warmth 토큰 오류로 단정하지 않으며 기존 Surface/Selection/Achievement/Growth 토큰을 유지한다. Chrome에서 정상 확인된 UI를 근거 없이 바꾸지 않는다. 네이티브 폼 컨트롤과 일반 HTML 컴포넌트의 색상 처리 차이를 함께 조사하고, 브라우저 문제에 대한 CSS 우회는 재현·원인 증거와 정상 브라우저 회귀 확인 후에만 검토한다. 실기기에서 해결을 확인하지 못하면 미해결로 기록한다. 현재 삼성 인터넷 문제는 [호환성 TODO](COMPATIBILITY_TODO.md)에 **운영 스위치 변경 후 실기기 재검증 대기**로 남겨둔다.

- 모바일 너비부터 디자인하고 작은 화면의 기록·별점·달력·계정 패널을 먼저 확인한다. 기존 `.habit-card`, `.star`, `.tabs`, `.day-tile`, `.modal`, `.panel`, 버튼 스타일을 우선 재사용한다.

- 새 습관 템플릿은 추가 모달 안의 간결한 선택 버튼이며 이름·아이콘·추천 시간대·매일 반복만 채운다. 선택만으로 저장하지 않고 나머지 항목은 사용자가 편집한다. 수정 모달에는 보이지 않는다.
- Habit Configuration은 습관의 기본 설정과 삭제만, Daily Reflection은 오늘의 별점·감정 키워드·메모·단순 체크만 다룬다. 서로의 입력을 중복 배치하거나 저장 경계를 혼합하지 않으며 과거 기록과 기존 사용자 데이터를 보존한다.

- 마지막 격려 문구는 기존 한 줄을 보존하고, 카드로 보이지 않는 아주 약한 테마 색상 안개와 **장식용 작은 별빛 2개**만 추가한다. 홈 메인 푸터의 원화·로고·파형·높이는 변경하지 않는다.
- 회고 엔진·날짜 기준·추천 로직·계정 동기화·Android 동작·DB 스키마에는 영향이 없어야 한다.

## V3.2 시그니처 별자리 아트 (구현된 성장 화면)

V3.2는 [시그니처 별자리 설계](CONSTELLATION_V3_2.md)를 따른다. **Emotional Minimalism은 모든 그림을 단순화하라는 뜻이 아니다.** 홈/설정/기록의 조작 UI는 단정하게 유지하되, 성장 별자리 아트는 별하루의 대표 작품이므로 풍부한 성운 레이어·골드 광채·정교한 별자리 조형과 단계별 시각적 보상을 강조한다. 단순한 별 아이콘과 기본 연결선은 최종 품질 기준에 미달한다.

Stage 1~6 승인 원화는 모두 1024×1536(2:3)이며 `object-contain`으로 표시한다. 성장 카드·점수·문구·확대 감상은 원화와 분리된 UI다. 320px 모바일 실화면·다크/라이트·모션 감소·렌더 성능을 확인한다. Stage 6 이후에는 새 공식 임계값 없이 원화 주변의 작은 장식만 연속적으로 풍성해진다.

### 사용자 승인 Stage 6 기준 (2026-11-17)

[별자리 최종 승인 아트 기준](CONSTELLATION_V3_2.md#2a-stage-6-시그니처-아트--사용자-승인-시각-기준-2026-11-17)은 **금빛 하이라이트가 은은하게 감도는 신화적 별빛 사슴**이다. 진주빛 라벤더/청보라 몸체와 샴페인 골드 뿔, 유려한 오로라 리본, 수정 무대와 회전 금빛 은하 고리를 시그니처 요소로 사용한다. 기존 순수 SVG 별/선 원형은 역사적 탐색 자료이며 최종 디자인이 아니다. Stage 1~6의 승인 원화 PNG와 WebP는 `public/assets/constellation/`에 포함되어 있고 이미지 바이트를 임의로 수정하지 않는다. 일반 앱 UI의 간결함과 대표 일러스트의 풍성함은 구분한다.


## 동기화 하단 안내 V2 — 작은 플로팅 카드 (2026-11-22)
- 일시적인 클라우드 동기화 오류는 3.5초간 조용히 대기 후 지속된 경우에만 한정된 크기의 카드 노출. 8초 후 자동으로 닫고, 성공 시 즉시 제거. 사용자는 X로 일찍 닫을 수 있다.
- 같은 오류는 5분 내 반복 노출하지 않음. 앱 내부 오류, 미전송 Outbox, 백업, 계정 상태는 카드 표시와 별개로 보존한다. 계정/데이터 관리에는 실패 상태가 남는다.
- 일시적 오류는 '동기화를 잠시 완료하지 못했어요 / 이 기기에 저장된 기록은 유지돼요' 및 '다시 시도' 1개. 기존 `app.sync()` 호출을 재사용하고 진행 중 이중 터치를 금지한다.
- 인증 만료, 저장 실패, 가져오기·복구/알 수 없는 오류는 자동으로 숨기지 않는다. 각 상황에 맞는 상세/로그인 진입점을 제공하며 사용자가 X로 카드만 닫을 수 있다. 데이터 상태 자체를 지우지 않는다.
- 현재 `storageWarning`은 테마 설정 로컬 저장 실패에서 발생할 수 있으므로 저장된 습관 데이터 손실처럼 표현하지 않는다. 이 경고는 '일부 화면 설정을 저장하지 못했어요'로 구분한다.
- 라이트/다크 토큰 `--surface`, `--selection-bg`, `--ink`, `--body`, `--line` 사용. 카드 좌우 여백 16px 이상, 버튼 44px, 하단 안전 영역 고려. 실기기 Chrome/삼성 인터넷 및 Android 재검증 필요.


## 예정 시간과 Android 습관 알림 정돈 (2026-11-22)
- 습관 생성·수정 화면에서 예정 시간 입력의 포커스 강조를 입력창 내부의 한 개 테두리로 제한하고, 알림 영역과 18px 간격 및 얇은 구분선을 둔다. 알림 제목·보조 설명·토글을 한 행으로 정렬하고 56×44px 터치 영역을 유지한다.
- 밤(17:00~04:59), 낮(11:00~16:59), 아침(05:00~10:59) 범위에 따라 시간을 직접 고르면 시간대 탭도 자동 동기화한다. 이미 시각을 선택한 상태에서 다른 시간대로 바꾸면 그 시간대의 권장 시각(08:00/13:00/21:00)으로 조정한다. **시각 미설정은 계속 선택 사항으로 유지**한다.
- 사용자가 직접 선택한 시각은 템플릿으로 덮어쓰지 않으며 그 시각에 맞는 시간대도 보존한다. Android 알림 시간 선택 시 기본 ON 및 수동 토글 우선 정책은 변경하지 않는다.
- 삼성 One UI 실기기의 포커스 경계 및 네이티브 시각 선택기는 CI만으로 완전 검증되지 않으므로 PR 병합 후 실제 기기로 재검증한다.
