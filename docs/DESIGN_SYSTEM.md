# 디자인 시스템 — Starlit Warmth

기준 파일: `app/globals.css`, `app/layout.tsx`, `components/byeolharu.tsx`, `components/starlit-hero.tsx`. Emotional Minimalism, Intuitive by Design, Progress over Perfection을 유지하고 밤하늘·황혼·별빛·성장의 의미를 역할별로 분리한다. 히어로 이미지와 감성 문구는 보존한다.

## 색과 글꼴

| 역할 / 토큰                                   | 라이트                | 다크                  | 사용                        |
| --------------------------------------------- | --------------------- | --------------------- | --------------------------- |
| Surface `--bg` / `--surface`                  | `#F7F6F2` / `#FFFFFF` | `#0C111B` / `#171D29` | 페이지 / 카드·모달          |
| Text `--ink`                                  | `#303847`             | `#F4F1E9`             | 기본 텍스트                 |
| Control `--control-bg` / `--control-border`   | `#F0EEE9` / `#D9D5CF` | `#252B38` / `#465061` | 미선택 컨트롤의 채움 / 경계 |
| Selection `--selection-bg` / `--selection-fg` | `#62547E` / `#FFFFFF` | `#695A85` / `#FFFFFF` | 선택·활성 상태              |
| Achievement `--gold`                          | `#C9A46A`             | `#E5B76E`             | 별점·성취                   |
| Growth `--sage`                               | `#526F65`             | `#B6CEB9`             | 진행·성장·포커스            |

기존 `--muted`, `--body`, `--line`, `--soft`, `--accent`, `--sage-soft`, `--gold-soft`, `--danger`는 각 사용처의 의미를 유지한다. 골드와 세이지를 선택 버튼의 배경으로 혼용하지 않는다. 골드는 배경·별 아이콘처럼 쓰고 작은 텍스트에는 충분히 진한 `--accent`를 쓴다. 텍스트 대비는 일반 글자 4.5:1, 큰 글자와 중요한 비텍스트 경계는 3:1 이상을 목표로 양쪽 테마에서 계산·화면 검증한다.

Noto Sans KR Variable을 자체 제공하고 이모지에는 시스템 폰트와 로컬 Color Emoji 대체 글꼴을 사용한다. 선택된 이모지는 글리프 색상을 바꾸지 않고 채워진 배경, 대비 경계와 체크 표시로 구분한다.

## 선택 및 테마 규칙

신규 선택형 버튼·탭·요일은 미선택일 때 중립적인 `--control-bg`, 선택 시 `--selection-bg`와 `--selection-fg`로 즉시 구별한다. 선택은 굵기·경계 또는 체크 표시로도 드러내고 `aria-pressed`(탭은 `aria-selected`), 키보드 포커스와 최소 44×44 CSS px 터치를 보장한다. 프리셋의 선택 여부는 현재 월~일 집합과 정확히 일치할 때만 참이다. 이모지와 별점은 고유 색을 유지한다. 설명 문구나 범례로 모호한 상태를 보완하지 않는다.

앱의 명시적 라이트·다크 테마가 OS 선호보다 우선한다. `.byeolharu`에 각각 명시적 `color-scheme`과 토큰을 적용하고 하위 `<dialog>` 및 네이티브 입력이 이를 상속한다. 테마 변경은 입력·선택 상태를 재생성하지 않는다. Android 브라우저의 강제 다크 모드는 별도 실기기 검증 대상이며 CSS만으로 통제된다고 가정하지 않는다.

### 브라우저별 색상 호환성

OS 테마, 브라우저의 웹페이지 강제 다크 모드, 별하루 앱 테마를 각각 식별한 뒤 표시 결과를 비교한다. 특정 브라우저의 색상 변환을 Starlit Warmth 토큰 오류로 단정하지 않으며 기존 Surface/Selection/Achievement/Growth 토큰을 유지한다. Chrome에서 정상 확인된 UI를 근거 없이 바꾸지 않는다. 네이티브 폼 컨트롤과 일반 HTML 컴포넌트의 색상 처리 차이를 함께 조사하고, 브라우저 문제에 대한 CSS 우회는 재현·원인 증거와 정상 브라우저 회귀 확인 후에만 검토한다. 실기기에서 해결을 확인하지 못하면 미해결로 기록한다. 현재 삼성 인터넷 문제는 [호환성 TODO](COMPATIBILITY_TODO.md)에 **운영 스위치 변경 후 실기기 재검증 대기**로 남겨둔다.

## 화면과 컴포넌트

- 모바일 너비부터 디자인하고 작은 화면의 기록·별점·달력·계정 패널을 먼저 확인한다. 기존 `.habit-card`, `.star`, `.tabs`, `.day-tile`, `.modal`, `.panel`, 버튼 스타일을 우선 재사용한다.
- 별점은 누르는 즉시 화면과 저장에 반영되고 같은 값을 다시 누르면 취소된다. 연속 입력 중에는 카드 순서를 잠시 고정한 뒤 완료 카드를 아래로 정렬한다. 성공 토스트 대신 별점·완료 상태·별빛을 피드백으로 사용하고 저장 실패는 별도로 알린다. `aria-pressed`, 완료 상태, 저장/오류 표시를 시각·음성으로 명확히 전달한다. 미완료에 죄책감을 주지 않는다.
- 새 습관 템플릿은 추가 모달 안의 간결한 선택 버튼이며 이름·아이콘·추천 시간대·매일 반복만 채운다. 선택만으로 저장하지 않고 나머지 항목은 사용자가 편집한다. 수정 모달에는 보이지 않는다.
- Habit Configuration은 습관의 기본 설정과 삭제만, Daily Reflection은 오늘의 별점·감정 키워드·메모·단순 체크만 다룬다. 서로의 입력을 중복 배치하거나 저장 경계를 혼합하지 않으며 과거 기록과 기존 사용자 데이터를 보존한다.
- 기존 밤하늘 히어로와 따뜻한 인사·격려 문구는 브랜드 요소다. 중복 카드·배너·토스트를 줄이더라도 유용한 감성 문구를 일괄 삭제하지 않는다.
- 기본 터치 대상은 44×44 CSS px 이상으로 계획하고 실제 모바일 뷰포트에서 겹침·가로 스크롤을 점검한다. 키보드 접근, `:focus-visible`, 명확한 레이블, 스크린리더 상태, 오류 피드백을 확인한다.
- 모달은 데이터 파괴·명시적 동의 등 필요한 순간에만 쓴다. 기록에 불필요한 확인 단계를 추가하지 않는다. 라이트·다크 모두에서 선택/비선택/비활성/오류를 확인한다.

UI 변경은 자동 테스트와 별도로 실제 화면에서 모바일·두 테마·키보드·스크린리더 레이블을 점검한다. 자동 검사만으로 감성/시각 완성도를 판정하지 않는다.
